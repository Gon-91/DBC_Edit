# Architecture

이 프로젝트는 **DBC 파일을 로드·편집·저장하기 위한 데스크탑 GUI 애플리케이션**이다.  
UI와 데이터 로직을 명확히 분리하여 유지보수성과 확장성을 확보하기 위해  
**MVC(Model–View–Controller) 패턴**을 기반으로 설계하였다.


## 1. Architectural Pattern

### MVC 선택 이유
- DBC 데이터 구조(Model)가 UI(View)에 종속되지 않도록 분리
- PySide6 Widget 구조와 잘 맞음
- Message / Signal 단위 기능 확장이 용이함

> Model은 UI를 모르고,  
> View는 데이터를 직접 수정하지 않으며,  
> Controller가 둘 사이를 연결한다.

---

## 2. Model

> **DBC 데이터 자체를 표현하고 관리하는 계층**  
> UI와 완전히 독립적이다.

### Core Models
- **DBCFile**
  - DBC 파일 전체를 표현
  - Message 목록을 소유
- **Message**
  - CAN Message 정의
  - ID, Name, DLC, Signal 목록 포함
- **Signal**
  - Message 내부 Signal 정의
  - Bit position, length, factor 등 포함

### Responsibilities
- DBC 파일 파싱 (file → model)
- DBC 파일 직렬화 (model → file)
- 데이터 무결성 유지
- UI 로직을 포함하지 않음

---

## 3. View

> **사용자 인터페이스를 담당하는 계층**  
> 데이터 변경은 직접 수행하지 않는다.

### Widgets
- **DBCFileLoaderWidget**
  - 파일 열기 / 저장 UI
- **MessageListWidget**
  - Message 목록 표시
- **SignalListWidget**
  - 선택된 Message의 Signal 목록 표시
- **MessageSignalLayoutWidget**
  - Message / Signal 비트 레이아웃 시각화

### Responsibilities
- 사용자 입력 처리
- Model 데이터를 화면에 표시
- 사용자 이벤트를 Controller에 전달
- 비즈니스 로직을 포함하지 않음

---

## 4. Controller

> **View의 이벤트를 받아 Model을 조작하는 중재자 역할**

---

### 4.1 DBCFileController

#### Responsibilities
- DBC 파일 열기 / 저장 처리
- View ↔ Model 연결

#### Actions
- **Open**
  - 파일 선택
  - file → Model 로딩
- **Save**
  - Model → file 저장
